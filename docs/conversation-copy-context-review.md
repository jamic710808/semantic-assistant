日期：2026-10-14。範圍：使用者提供的 ABI 回答、目前開啟的兩套助手視窗、重建版原始碼，以及既有 ABI 靜態分析證據。

## 結論

兩邊這次對四張表與五個度量值的理解確實相近；重建版的主要缺口是**模型關係沒有完整交給 AI 分析回合**。畫面左側已顯示兩條關係，不能據此推定 AI 收到了相同資訊。另有明確的顯示問題：對話使用不可選取的 WPF TextBlock，且 Markdown 以原始文字顯示。

這些差異有來源及實際回答證據，不能只歸因於模型名稱、思考等級或模型能力。也不能從一個題目的相似回答，證明整套分析鏈路已完整 1:1。

## 2. 原因與程式鏈路

### 2.1 不能選取或複製

重建版 `MainWindow.xaml` 原本以 TextBlock 顯示 Transcript，沒有文字選取與對話複製按鈕；ResultDetails 也使用 TextBlock。這個問題與 AI 模型沒有關係。

ABI 的 `WebResources/index.html` 使用 HTML 內容顯示，另有 `copyMessage`；它先嘗試把 HTML 與文字一起寫入剪貼簿，失敗時改複製文字。因此，原版的複製與格式化能力不是單純按鈕外觀。

### 2.2 左側看得到關係，AI 沒有取得完整關係圖

原流程：

```text
Desktop/TMDL reader
  → ModelSnapshot（已含欄位、度量值、單欄關係與篩選屬性）
  → ModelContextBuilder（原本只有來源、合成標記、表名）
  → ConversationInstructions + 使用者提問 + 受控歷史
  → AI 自行選工具
  → get_table_details（單表欄位與度量值，不含關係）
  → AI 回答
```

上一階段加入的 `get_model_edit_context` 雖能在有寫入服務的來源讀到部分原生關係，但它主要服務修改前的定義與所有權核對；一般結構介紹沒有要求使用它，離線來源也不提供該服務。不能把它當作所有來源都可用的唯讀模型概覽。

ABI 靜態主視窗鏈路可見：呼叫 `StreamChatWithToolsAsync` 時傳入 `_currentModel`、`_currentReport`、配置與工具；相關表工具也可序列化原生關係。這與重建版原先的精簡摘要不同。但 Core 部分不可完整讀取，**無法由這些呼叫宣稱已重建 ABI 的精確系統提示詞、完整 HTTP payload 或所有分析策略**。

### 2.3 同模型不保證逐字相同

重建版 API 請求由自己的系統指令、模型摘要、歷史、工具清單與工具結果組成。端點、模式、授權、上下文預算及工具回合限制，都能影響 AI 看到的資訊。本版預設摘要 2,000 字元、6 輪、8 次工具呼叫。

請求程式未指定 temperature、top_p 或 seed；這不表示供應商實際使用哪個預設值。本輪沒有兩邊的 HTTP 請求紀錄，無法量化採樣、供應商路由或推理參數的影響。來源及回答相似，也不能證明模型版本與歷史完全一致。

## 3. 本輪修正

1. Transcript 與 ResultDetails 改成唯讀 TextBox，可選取文字與使用 Ctrl+C；保留唯讀狀態。
2. 新增「複製最新回答」：複製最新成功完成的 ReportDocument.Markdown，避免混入回合／工具事件。
3. 新增「複製全部對話」：複製目前顯示的 Transcript，包含工具與回合事件。剪貼簿寫入失敗會顯示可重試的訊息。
4. 新增 `get_model_overview` 唯讀工具：取得表／欄位／度量值清單、完整數量、關係端點、啟用狀態、基數、交叉／安全篩選屬性及未連接表。它使用既有 MetadataRead 與當回合中繼資料外送授權，不需要允許修改模型，也不執行 DAX。
5. 初始摘要加入模型數量與預算內的關係定義，明確標示關係摘要覆蓋範圍；完整資訊另由概覽工具提供，公式另讀表細節。
6. 系統指令要求模型結構介紹先讀概覽、核對關係，並區分用途推論與已讀取事實。
7. TOM／TMDL 投影新增未支援關係名稱；關係投影不完整時，不把「沒有已投影關係」誤判為「完全未連接」。概覽超過結果預算時明確拒絕，不默默截斷後聲稱完整。

內建工具由上一階段 14 個增為 15 個。完整概覽仍受既有結果大小限制；日期表標記、排序、RLS、報表頁面與視覺內容不在本工具投影範圍。

後續已依使用者要求調整對話呈現：主對話只顯示提問與最終回答，「複製全部對話」不再包含工具事件。技術過程移到側面板預設收合的執行紀錄；詳 [對話顯示修正](clean-conversation.md)。上文描述的是該項調整前的調查與交付。

## 4. 完成與未完成界線

已完成：讀取兩套正在開啟的助手及當前回答、來源程式對照、上述修正、Release 建置。建置成功，0 警告、0 錯誤，23.20 秒。根目錄啟動器已指向 `artifacts/conversation-copy-context-20261014`。

尚未驗收：新版本的 UI 文字選取／剪貼簿實際操作、真實供應商是否呼叫概覽工具、重跑同題後的答案及所有模型關係旗標逐項對照。本輪沒有新增或執行測試，也沒有發送新 AI 回合；建置成功不能代替這些結果。

仍有呈現差異：這次支援選取與複製的是純文字／原始 Markdown，**沒有完成 ABI 的格式化 Markdown 顯示、HTML＋文字雙格式剪貼簿、每則訊息的獨立複製／重試與圖表操作**。不能宣稱對話呈現已完整 1:1。

既有開啟視窗仍使用舊版且保留原回合；新程式不會自動套用到既有視窗。可先保留所需內容，再由根目錄啟動器開啟新版。既有完整聊天沒有預設持久化，重啟不能恢復原回合或授權。

## 5. 下一步對照方式

同題對照應先固定：同一報告與模型版本、相同完整端點與模型、相同使用者提示、相同模式、兩邊新對話及足夠的中繼資料授權。觀察 `get_model_overview`、必要表細節工具是否成功，將回答的數量、欄位、公式、關係端點與旗標逐項核對。

通過標準是證據一致、關係判讀正確、推論有標記與內容可複製，不應要求模型逐字產出 ABI 的舊答案。後續介面對齊應補格式化訊息及訊息個別操作；完整分析鏈路另需補報表頁面／視覺、日期與排序、RLS 等脈絡。
