# 可選歷史保存（History Store）

日期：2026-10-13。

## 保存政策與使用

桌面「本機歷史與保存政策」提供兩個獨立選項：回合摘要、已匯出HTML報告索引。兩者預設關閉；關閉時完成回合／匯出不建立歷史目錄、檔案或鎖檔。勾選保存並按「保存政策」才啟用。

- 摘要：ID、UTC時間、五工作流程之一、來源類型、成功／拒絕／取消／失敗及工具結果次數。
- 產物索引：上述固定欄位及宿主生成的HTML檔名；沒有檔案內容。
- 沒有對話文字、模型名稱或ID、DAX、查詢資料列、provider／endpoint、帳號、key、token、session或操作同意欄位。

回合完成時從受限欄位生成摘要；AI生成文字不能作為摘要輸入。主視窗與Dashboard成功匯出的報告可建立索引。歷史視窗只顯示報告位置與目前是否存在，沒有執行檔案、重新查詢、重連模型、重用結果或恢復權限。

保留期限1–30天，預設7天；最多1–100筆，預設50筆，摘要與產物共用上限。到期不顯示，下一次保存／移除／政策更新整理實體索引。停用某一類會清除該類索引；清除全部保留政策，移除單筆只作用該ID。這些操作均保留已匯出的HTML檔案。HTML本身可能含已同意匯出的數值，依其原有保存與外送契約處理。

## 路徑與檔案契約

正常宿主固定使用自己的 %LOCALAPPDATA%/SemanticAssistant/history/history.json；報告位置由自己的 reports 目錄加上嚴格 report-日期-時間-隨機ID.html 檔名組成，不保存完整路徑或接受AI路徑。每個smoke均注入artifact下的自有歷史store，沒有讀取使用者歷史。

版本1，128000 UTF8 bytes上限、深度8、最多100筆；必填欄位、命名列舉、未知／重複欄位、重複ID、非法時間／模式／來源／狀態拒絕。無效、未知版本與不可用檔案保留，拒絕保存或清除。沒有自動降版或對未知內容作刪除。

保存使用同目錄CreateNew暫存、Flush(true)及原子替換；history.lock的FileShare.None協調獨立store／視窗，取得鎖後重新讀取，競爭時直接失敗而不覆寫。只清理當次確實建立的暫存檔。路徑不接受UNC、符號連結或重新解析點；這不是同一OS使用者惡意競態的完整沙箱，也不保證突然斷電時檔案系統目錄已落盤。

歷史保存失敗不把成功回合或報告改成失敗，桌面提供固定提示，不記錄私有例外內容。索引為普通本機JSON；它不含敏感內容的設計不等於加密或安全抹除。時鐘被大幅調回且已有未來紀錄時，讀取可能拒絕；原檔仍保留。

## 驗證

HistoryStoreTests包含28項自製fixture案例：預設關閉、跨store重載、獨立類別同意、容量／期限、移除／清除保留HTML、無效／future／秘密欄位／UTF8／大小／重複ID、非法列舉、路徑與mutation lock。

WPF歷史流程用實際MainWindow回合及HTML匯出、政策表單控制、第二個視窗重載、列表／移除／清除；確認沒有恢復query、結果或session。第二個視窗使用同一注入store，獨立FileHistoryStore重載則由核心測試覆蓋；不稱為完整OS重啟。全部使用自己的合成資料，沒有操作Power BI。最終完整與封裝結果見 verification.md。

目前不保存可供重播的完整對話、不索引模型寫入稽核、不刪除HTML檔案；模型修改audit有自己的durable intent契約。共同工具registry已加入；真實服務與公開授權／release仍需後續工作。
