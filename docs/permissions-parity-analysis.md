# 權限管理：ABI 行為與重建版差距

日期：2026-10-14。範圍：使用者兩張權限管理截圖、本機 ABI 靜態分析、重建版原始碼對照。
本文保留研究階段的差距與改善方案。後續獨立視窗與模型修改總開關已實作，完成範圍及使用方式見 [model-permissions.md](model-permissions.md)。研究階段未操作 ABI 原生視窗或 Power BI 模型。

## 結論

目前重建版的權限管理入口沒有按照 ABI 還原。它把當次查詢、匯出、外部工具與執行設定集中到側面板，卻沒有 ABI 的持久模型修改總開關。

重建版的授權種類較細，不能據此宣稱產品功能較完善，更不能宣稱已達 1 比 1。使用者要求的是先還原 ABI 的介面與操作語意；後續擴充必須保留此基準。

## 1. ABI 視窗各項目代表什麼

| 可見項目 | 對應作用 |
|---|---|
| 權限管理 | 獨立對話框；MainWindow 開啟 PermissionsWindow |
| 允許 ABI 智能助手修改數據模型 | 布林設定 AllowModelModification；控制助手的模型修改能力 |
| 已勾選 | 視窗讀取的已保存設定為 true，或使用者尚未保存的勾選草稿；僅憑截圖不能判斷是安裝預設 |
| 取消勾選／安全模式 | 阻擋修改模型的路徑；仍可保留模型讀取、數值查詢與獨立 HTML 輸出 |
| 保存 | 重新讀取 AppConfig，更新這一個布林值，呼叫 ConfigService.Save，然後關閉 |
| 取消 | 關閉，該事件沒有保存此次勾選值 |

這是助手的操作策略，不會替使用者授予 Power BI / XMLA 帳號權限，也不會改變 DAX 公式的正確性。

### 已確認的靜態流程

```text
開啟權限管理
  → PermissionsWindow
  → ConfigService.Load
  → 以 AllowModelModification 填入核取方塊

按保存
  → 重新載入設定
  → 將核取方塊值保存為 AllowModelModification
  → ConfigService.Save
  → 關閉

操作模型／分派工具
  → 檢查模型修改設定及相關工具策略
  → 關閉時限制修改操作
```

MainWindow 可見的限制包含建立表、更新描述、文字指令與工具執行等路徑，並有依設定使用唯讀工具集合的分支。
唯讀工具的預設備援名稱可見 get_table_details、execute_dax_query、generate_html_report_file；雲端工具策略可影響集合。
其中「唯讀」是相對於資料模型：產生 HTML 檔案仍會寫入本機檔案。

主程式亦有 update_measure、delete_measure、rename_object、set_format_string、update_relationship、generate_html_report_measure、generate_dashboard_measures 等修改工具識別字。這證明靜態候選工具存在，不代表本輪已驗證每個工具能成功執行。

## 2. 我們現在每個項目的意義

### 截圖中可見項目

| 項目 | 實際程式作用 | 是否相當於 ABI 開關 |
|---|---|---|
| 當次回合權限 | 建立 PermissionSession 時使用的能力集合；包含來源、操作模式與授權版本 | 否 |
| 允許目前模型數值查詢 | 建立回合時加入 DataQuery，允許 execute_dax_query；關係／欄位／DAX 等模型中繼資料使用另一個 MetadataRead 能力 | 否，查詢不會修改模型 |
| 允許匯出本機 HTML | 匯出時建立 ArtifactWrite 授權，將有效查詢結果保存為本機 HTML；操作完成後清除此匯出同意 | 否，本機檔案不是模型定義 |
| 允許 AI 提出已匯入工具呼叫 | 有明確匯入的工具時加入 ExternalTool，讓 AI 可提出呼叫；執行仍顯示參數並逐次確認 | 否，外部工具也可能有未知副作用 |
| 數值查詢預設關閉 | 現有產品的額外限制；ABI 的模型安全模式不是相同查詢開關 | 否 |
| AI 外送另需逐回合同意 | AiDialogs.Consent 為使用者訊息、中繼資料、查詢結果、外部工具資料分別建立 EgressConsent | 否，控制傳給 AI 的資料 |
| 取消撤銷當次授權 | 主畫面的取消操作呼叫 PermissionSession.Update 清空能力並取消回合 | 否，不是保存全域模型修改設定 |
| 本機執行預算 | 修改摘要、查詢與 AI 工具迴圈的大小／時間上限；保存設定並清除舊回合授權 | 否，是執行限制 |
| 使用本機模擬 AI | 將 AiProvider 設為 null，保留模型設定清單；合成來源使用 DemoAiProvider，真實來源沒有供應商時只保留結構檢視 | 否，也不是安裝本機大型語言模型 |
| 右上 × | OnCloseUtility 只將側面板收起；不取消正在執行的回合，不保存或撤銷權限 | 否 |

三個核取方塊的即時狀態沒有存入 AssistantSettings。模式／來源／供應商切換會清除相關授權；外部工具勾選在回合結束清除，匯出勾選在匯出結束清除。查詢勾選沒有在每個回合結束一律清除，因此不能把所有項目說成「每次送出必須重勾」。

沒有明確匯入外部工具時，外部工具核取方塊會停用；離線 TMDL 來源不提供數值查詢。這解釋截圖中部分項目灰色的原因。

### 本機執行預算的九個欄位

| 欄位 | 意義 | 現有最大值 |
|---|---|---|
| 摘要表數 | 給 AI 的模型摘要最多納入幾張表 | 20 |
| 摘要字元 | 模型摘要文字上限 | 2000 |
| 查詢列數 | 一次查詢最多回傳資料列數 | 100 |
| 查詢 UTF-8 大小 | 查詢結果編碼後的大小上限 | 64000 bytes |
| 查詢秒數 | 單次查詢期限 | 30 秒，本機最多 10 秒 |
| AI 回合數 | 工具結果回送 AI 的迴圈上限；不是聊天室總提問數 | 6 |
| 工具呼叫數 | 一次送出流程中的工具呼叫上限 | 8 |
| AI 輸出字元 | 一次送出流程中的輸出量上限 | 20000 |
| 整輪秒數 | 一次送出至工具迴圈結束的期限 | 120 秒 |

### 三個分頁與其他入口

| 分頁 | 內容與用途 |
|---|---|
| 權限 | 上述查詢、匯出、外部工具、預算與模擬 AI |
| 來源與工具 | TMDL 資料夾、內附範例、重讀、合成示範、雲端登出；MCP 連線／匯入／清除；模型修改預覽、Dashboard 計畫、五種操作模式 |
| 結果與匯出 | 查詢結果與來源、圖表類型選擇、本機 HTML 匯出、AI Dashboard 提案檢視 |

這三頁本質上是綜合操作面板，不應以同一個「權限管理」入口冒充 ABI 的單一開關對話框。

## 3. 程式層面的實質差距

1. AssistantSettings 尚無 AllowModelModification 或等價的持久政策。
2. OnShowPermissions 直接呼叫 ShowUtility(0)，沒有獨立保存／取消視窗。
3. ToolRegistry 的內建 AI 工具目前只承認 get_table_details、execute_dax_query、propose_dashboard；propose_dashboard 是提案，不直接修改模型。
4. 模型修改由人工開啟 ModelWriteWindow 或 DashboardWindow。ModelWriteWindow 在預覽及勾選當次同意後，加入 DefinitionWrite 並執行。
5. 三個截圖核取方塊都沒有直接控制 DefinitionWrite；即使全部未勾選，仍可另行開啟模型修改流程並確認寫入。
6. 當前寫入器限制自有物件並執行回讀／補償；ABI 靜態候選工具涵蓋更新、刪除、重新命名等較廣操作，尚非相同能力。
7. AI 外送與工具逐次確認是重建版現有的互動設計。隱藏權限面板不會自動使這些流程與 ABI 一致。

所以：我們有分層授權與逐次預覽的工程基礎，但缺少使用者期待的全域策略與同樣的 AI 修改工具鏈；不能說現在的頁面做得比較完善。

## 4. 按 1 比 1 目標改善

### 第一層：還原頁面與保存語意

- 權限管理按鈕開啟獨立視窗，參照提供的大小、淡色背景、標題、單一核取方塊、提示文字、取消與保存按鈕。
- 核取方塊表達「允許本助手修改資料模型」；提示清楚說明關閉為安全模式。
- 打開載入已保存值；取消與 × 捨棄尚未保存的修改；保存後生效並可跨重新啟動。
- 在本專案設定中加入同等布林欄位，保存前保留舊設定；不從查詢／匯出／外部工具勾選值推導此旗標。
- ABI 安裝預設值尚未知，須明確記錄重建版初始值，不能把截圖勾選狀態當成預設證據。
- 現有查詢、匯出、MCP、預算與模擬 AI 入口移回相關操作區，保持「權限管理」視窗只有 ABI 的項目。

### 第二層：建立真正共用的模型修改政策

- 新增應用層 ModelModificationPolicy；布林設定是持久偏好，實際政策帶版本，供執行流程核對。
- 關閉時仍可讀結構、做允許的查詢、產生提案與獨立 HTML；不得建立／修改／刪除模型物件。
- 在所有寫入路徑檢查，包括人工模型修改、HTML 度量值、Dashboard 指標／HTML、未來 AI 修改工具與回復操作。
- 應用層分派與寫入邊界都要檢查，不能只停用畫面按鈕；關閉政策時舊寫入授權／預覽不能繼續使用。
- 已開始的外部寫入不保證能取消或回復，需準確報告狀態。關閉設定後如何處理本次補償／還原，必須有明確規則，不能任意阻斷清理。
- 開啟只解除助手層的模型修改限制；不取代 Power BI 帳號權限、來源版本檢查或有效寫入參數。
- 一般外部 MCP 工具不能僅憑名稱被認定為唯讀；其可修改模型或其他環境的能力須與全域模型策略分清。

### 第三層：補上 ABI 的 AI 修改工具鏈

如果 1 比 1 包含勾選後的「AI 可直接修改模型」操作，還要擴充受控 AI 寫入工具、參數驗證、結果回讀、失敗處理與持久政策整合。

目前的人工預覽／逐次同意不能假裝等於這種互動；保留時須列為明確差異。也不能僅移除確認視窗，就聲稱已取得相同工具能力。
ABI 在所有情境是否直接執行、是否另有確認尚未證實；應逐情境還原有證據的行為，不推定所有修改都無確認。

## 5. 驗收條件與接續位置

- 視窗只有原圖對應項目；尺寸、間距、文案及按鈕行為逐項對照。
- 修改後取消／關閉不保存，保存後重新啟動仍保留。
- 全域關閉：所有模型寫入入口均被拒絕；唯讀查詢與獨立 HTML 路徑保持可用。
- 全域開啟：符合實際來源權限與工具條件的模型修改可進入執行流程。
- 政策切換不沿用舊的寫入授權；進行中的寫入與補償結果明確呈現。
- AI 修改工具實際成功、回讀相符後，才可稱對應的直接修改流程完成。

建議立即實作第一層與第二層，形成可用的原樣權限視窗及真正總開關；再依已觀察的 ABI 操作情境補齊第三層。每一層的完成範圍單獨說明，不把畫面還原等同整套功能完成。
