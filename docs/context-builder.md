# 情境建構器（Context Builder）

日期：2026-10-13。

## 呼叫與授權

`ConversationCoordinator → MetadataRead／Metadata 外送檢查 → reader → session／source／外送期限重查 → ModelContextBuilder → provider`。

建構器是純文字格式化器，不自行連線、授權或取得資料。沒有讀取能力或外部 Metadata 外送同意時，不呼叫 reader 或選擇策略。讀取期間撤銷權限或模型版本改變，拒絕建立情境。AI provider 送出前仍沿用原本的期限與撤銷檢查。

## 選擇策略

- `FirstContextTables`：依 snapshot 順序選表。
- `PreferredContextTables`：先選宿主明確提供、目前來源存在的表名，再補其餘；未知或重複名稱略過。
- `IContextTableSelector`：可由可信宿主替換；只接收表名，沒有 DAX、欄位定義、連線字串或查詢列。未開放第三方策略載入，也不從 AI 訊息自動選擇策略。

桌面／CLI 目前使用預設策略；沒有新增偏好選擇介面。這是獨立策略契約，不代表已驗證真實模型的選擇品質。

## 大小與呈現

- `ContextBudget` 可降低預算；上限仍為20個表與2000個 UTF-16 字元，最小字元預算128。
- 名稱以 JSON 字串跳脫，避免換行或引號混淆欄位邊界；跳脫不保證消除名稱中的提示注入，工具仍須本機授權。
- 名稱整段放不下時略過，後續較短名稱仍可入選。來源名稱先限制128字元，跳脫後超出摘要預算則省略；不輸出半截 JSON 名稱。
- 只檢視策略產出的前256項，避免錯誤策略無限重複；可信策略本身的阻塞不屬任意程式隔離保證。
- 摘要僅含來源名稱、合成標記與表名；定義細節仍由既有按需工具與 Metadata 權限取得。

## 合成證據

`ContextBuilderTests` 覆蓋大小上下限、排序／去重／未知表、超長名稱、控制字元、預設20表限制、錯誤無限重複策略、實際 provider 邊界，以及缺少讀取／外送授權、來源更新與撤銷。沒有讀取使用者模型或送往外部 AI。
